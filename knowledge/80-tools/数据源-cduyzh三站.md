# 数据源 · cduyzh 三站

> 同一作者（cduyzh.top）的三个崩铁站，互补：**trend 给数值、hsr 给配速、archive 给通关样本**。
> 大人 2026-11-22 指定：「hsr-trend 很有用，里面有很多有用的数据」。

## 一、三站分工

| 站 | 定位 | 对本项目的用处 |
|---|---|---|
| **hsr-trend.cduyzh.top** | 终局观测站：四大模式历期怪物血量 / 弱点 / SPD / 韧性 / 环境 buff | ⭐ **补 40-enemies 的通用敌方属性**、补 50-stage 的环境与节点 buff 原文 |
| **hsr.cduyzh.top** | 配速与 Buff 计算器（行动实验室） | ⭐ **第三方排轴引擎**，可拿自己的引擎输出与之对照 |
| **hsr-archive.cduyzh.top** | 竞速档案（社区通关记录） | 查同阵容别人打到多少分、什么造价，定目标分 |

## 二、hsr-trend 栏目与 URL 规律

| 栏目 | URL |
|---|---|
| 混沌回忆 | `/trends/moc`（默认首页会 301 到这里） |
| 虚构叙事 | `/trends/fiction` |
| 末日幻影 | `/trends/doom` |
| 异相仲裁（王棋） | `/trends/peak` |
| 单期详情 | `/season/{moc\|fiction\|doom\|peak}/{期号}`，如 `/season/doom/3022`、`/season/moc/1037` |

**单期详情页给的字段（逐个可抄）**：

1. **节点血量构成**——每节点百分比 + 总 HP + 波次（例：#3022 节点1 18.41% / 19.36M、节点2 56.49% / 59.39M、星启 25.1% / 26.40M）
2. **本期环境效果 + 每个节点的三选一效果**——**技能原文**（含数值，如「欢愉度提高 10%/20%/30%/60%」）
3. **敌人阵容**——每只怪：内部 ID、`Elite` 难度档、Lv、弱点、单体 HP、**速度 SPD**、**韧性 Toughness**、总 HP（多阶段写 `HP x2` 与单阶段相乘）、机制简介

> 字段口径说明（站点自述）：数据直连底层官方数值表，HP **计入** HardLevelGroup 难度系数与 EliteGroup 精英倍率，多阶段 Boss 累乘各阶段 `phase_max_hp_ratio`。

## 三、⭐ 韧性口径：站点值 × 1.2 = 实战显示韧条（三例吻合）

这是本轮最有价值的发现。站点 Toughness 与我们的实测/推算值差一个固定系数：

| 怪 | 站点 Toughness | 我们的数 | 比值 | 我们的来源 |
|---|---|---|---|---|
| 合金机铠·帕姆王 | 400 | **480**（P1） | ×1.2 | 2026-11-22 大人实测 |
| 枯茎朽骨的引路人（死龙） | 800 | **960** | ×1.2 | 拆包推算 |
| 芒寒色正的银骑士（银枝） | 270 | **324** | ×1.2 | 拆包推算 |

三例全部 ×1.2，**不是巧合**。可用的换算：

```
实战 P1 显示韧条 = 站点 Toughness × 1.2
多阶段 Boss 后续阶段 = P1 × 阶段倍率（帕姆王 P2 = 480 × 1.75 = 840 ✓）
```

> 🟡 这 1.2 的**机制名**未定（可能是关卡难度组对韧性的统一加成）。不影响使用——工程上就是乘 1.2。
> ⚠️ 站点只给**单值**，多阶段 Boss 的 P2 不单列（帕姆王只写 400，P2 840 得自己按倍率推）。这一条与我们 `10-basics/韧性条口径.md` 的三套刻度是同一件事的第四个观测口径，已在那里登记。

## 四、⚠️ SPD 口径：站点值 ≠ 实战速度（待核）

帕姆王站点 **SPD 134**，而我们实测行动条反解是 **177**（周期 56.5 AV）——比值 **1.321**。

站点 SPD 看起来是**基础速度**（未乘关卡速度系数），与 HP 不同（HP 站点自述已乘难度系数）。**在用站点 SPD 之前必须先在实战里校一次**：

> 判别式：拿 #3022 节点 2 的枯茎朽骨（站点 144）。若实战速度 = 144×1.32 ≈ **190**，队列周期应 ≈52.6 AV；若等于 144，周期 ≈69.4 AV。抓一次队列帧即可定。

**结论：站点 SPD 只作「相对快慢」参考，绝对值走实测。** 这与 L0 红线 1（数值必须带来源）一致——不拿未校的口径直接进引擎。

## 五、hsr.cduyzh.top：现成的配速引擎（拿来做对照）

「星铁配速与 Buff 计算器 · 行动实验室」，功能与我们 `tools/axis-sim2.js` 高度重叠：

- **场景预设**：异相仲裁 0T/1T/2T = 300/400/500 AV，混沌回忆 0T/1T = 150/250 AV，可选截止点含/不含
- **资源约束三档**：理想行动轴（可强制开大）/ 严格能量 / 严格能量与战技点
- **角色配置**：星魂、速度模式（面板直接输入 / 基础值+修正）、光锥与叠影、**风套四件（终结技后自身提前 25%）**、行迹、充能绳
- **预设**：「舞舞舞·理想行动轴」「舞舞舞·严格能量」「星期日专锥 S1」
- 明确标注「小数比例 0.194 = 19.4%」，可导入导出配置

**用途**：①我们的引擎输出可以与它对照，两套算法同结论才算稳；②它的「严格能量 / 严格战技点」二档正好对应我们那条「资源台账横穿四层」的教训；③「角色档案 · 同步」说明它也在用 UID 面板。

## 六、hsr-archive：竞速档案

- 入口 `/archive`：按角色 / 关卡 / 造价筛选社区通关记录（阵容、命座、金数、分数）
- 文章路径规律：`/articles/alioth-{monsterId}`（Alioth 机制研究，4.7 三 Boss 已抓过 → `docs/data/末日幻影-P22-Alioth机制数值.md`）
- 数据更新时间可读（页面上直接印「数据更新于 …」）

**用途**：定目标分前先看同阵容天花板，避免把 3900 定成不可能或过低的数。

## 七、抓取方式（已验证）

站点是 **SSR**——`curl` 拉到的 HTML 里直接含全部数值，不需要跑 JS、不需要逆向接口：

```bash
curl -sL -m 30 "https://hsr-trend.cduyzh.top/season/doom/3022" -o page.html
# 注意必须带 -L：根路径 301 跳 /trends/moc
```

- 本环境 `curl` 对 `*.cduyzh.top` **可用**（与 GitHub raw 不同，不受网络策略限制）
- 数据缓存在站点侧，页面提示「首次加载会拉取并计算，按游戏版本缓存在本机」
- 页面右下角印**数据版本**（当前 `4.7.52`），抄数时连版本一起抄

## 八、使用规矩

1. **HP / 弱点 / 环境 buff** → 直接可用，连数据版本一起记（站点已计难度系数）。
2. **韧性** → 乘 1.2 才是显示值，多阶段自己推 P2。
3. **SPD** → 🟡 未校，只用相对快慢，绝对值必须实战反解。
4. **不复制数值进知识库**——具体某期某怪的数写 `docs/data/`，本节点只留「怎么查、字段是什么、口径怎么换」（L0 第 7 条）。
