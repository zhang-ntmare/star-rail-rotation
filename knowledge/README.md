# 排轴知识库 · knowledge

> **这个库负责「查得到」，`tools/axis-sim*.js` 负责「算得准」，`70-runs/` 负责「记得住」。**
> 排轴不是想出来的 —— 是把库里的机制全部捞出来、把参数代进引擎、把结果拿去验收。

## 为什么重建

旧 `docs/` 是按「谁先写谁先放」堆的：`characters/` 里同时装着角色卡、队伍协同、实战轴、对账记录；`data/` 里同时装着敌方数值、场地 buff、实录。
结果同一个机制散在三处、改一处漏两处，排轴时靠记忆去找 —— **找不到就靠猜**，这才是反复出错的根因。

新库按「排轴时你会问的问题」分区，不按文档类型分。

## 九区

| 区 | 回答的问题 | 什么时候读 |
|---|---|---|
| `00-rules/` | 哪些事**绝对不能做**、开工前必须查什么、还有哪些数没钉死 | 每次开工（必读） |
| `10-basics/` | AV/速度、回能/SP、乘区、击破、buff 结算、韧性、开怪、嘲讽 —— 不分角色不分怪的通用规则 | 建引擎 / 算账时 |
| `20-action/` | 谁能拉条、拉多少、什么时候触发（光锥/遗器/命座/角色/场地/boss 推条） | 第 2 层排轴 |
| `30-units/` | 某个角色到底怎么运作、数值多少、对轴意味着什么 | 用这个角色时 |
| `40-enemies/` | 某个怪多少血多少速、技能什么顺序、是老式固定还是机制随机 | 定敌方时序时 |
| `50-stage/` | 本期场地给什么 buff/debuff、什么时候生效 | 进场前 |
| `60-teams/` | 这四个人怎么协同、谁先谁后、循环骨架怎么转 | 配队时 |
| `70-runs/` | 某一次实战的完整轴、对账记录、别人的轴 | 出成品 / 复盘 |
| `80-tools/` | 数据从哪来、字段有什么坑、引擎怎么跑、结论被复查过几轮 | 取数 / 建工具时 |

**分层对应**（借 `ayaka-work/team/memory` 的五层提纯模型）：

| 层 | 在本库 | 意思 |
|---|---|---|
| L0 不许犯 | `00-rules/L0-红线.md` | 违反即报废，能写出判定逻辑 |
| L1 别再犯 | `00-rules/L1-排轴前清单.md` | 动作清单，做之前逐条过 |
| L2 想明白了 | 10/20/30/40/50/60 各区正文 | 提炼后的结论，可复用 |
| L3 这事归谁 | 各区 `_index.md` | 分类登记，按需读 |
| L4 发生过什么 | `70-runs/` + `docs/` 原文 | 过程流水，不进召回主池 |

**唯一权威原则**：同一份知识**只保留一份正文**。`docs/` 下的旧文件是原始副本，本库节点用 `source:` 指过去，不复制内容。要改结论就改 `docs/` 那份，然后更新节点的 `updated`。

**版本标记（必填）**：每个节点 frontmatter 都有 `game_ver`（当前 `"4.7"`）。数值随版本变，没有版本号就无法判断"这条还能不能用"。
版本更新后：受影响节点先重打一次确认，再改数值；不确定的一律降 `confidence`，不许沿用旧数当新数。

## 缺口（按区，排轴前必须知道缺什么）

| 区 | 现在有什么 | 缺什么（按优先级） |
|---|---|---|
| 10-basics | 五份通用规则 + 韧性口径 / 开怪机制 / 末日计分（2026-11-22 补齐） | 其余三模式口径（**暂缓，只做末日**）；嘲讽值——**按需**，只在凹生存/凹受击时才算 |
| 20-action | 本队 12 条算子（按 A 改速度 / B 改行动条 / C 额外行动 三类分开） | 全角色泛化：换队要重理，光锥/遗器/命座还没做成通用表 |
| 30-units | 5 角色 + 1 体系 | 全角色库（现状仅够欢愉战舰 + 布洛妮娅样板） |
| 40-enemies | 帕姆王/破晓/银枝/Alioth | **不做全图鉴**，只收「当前要打 / 计划要打」的怪；「技能序列」与「行动周期」待分列 |
| 50-stage | 本期末日 + 六类同构族 | 历期归档（按同构族合，不按期数） |
| 60-teams | 欢愉战舰 1 队 | 第二套队（不同命途）用于验证算子表是否通用 |
| 70-runs | 1 条主战场轴 | 轴改单表（九列：类型/观察条件/期望/实际/段标记） |
| 80-tools | 数据源、导入、别名 | **字段坑总表**（`max_sp` 实为能量上限这类）＋引擎参数出处表 |

## 怎么用（三个动作）

```bash
cd tools/kb
python kb.py build                      # 建索引（改完节点必跑）
python kb.py ls 40-enemies              # 看这一区有什么
python kb.py show 30-units/爻光          # 读节点
python kb.py recall 爻光 能量 普攻        # 排轴前召回：该读哪几份
python kb.py recall 帕姆王 韧条 破韧      # 按敌人召回
```

**排轴标准动作**：`recall` 出必读清单 → 逐份读 → 过 L1 清单 → 建 baseline → 加拉条 → 加机制 → 对账。跳哪一步都会返工。
