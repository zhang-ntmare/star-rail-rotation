# 整体重排：P1 优化与 100 AV 可行性

> **起因**：大人「P1 算得挺准，为什么转 P2 就什么都不算？P1 一直 1911 才转 P2、给 P2 只剩 11 AV，不该质疑 P1 吗？第一波爆发有两个银狼 3+1 打在 1/2 减伤上，让保姆再动一次强化 a 消减伤算不算提速点？用算法算一条 100 行动内通关的轴，这才是目标。错了就该推翻而不是继承。」
> **本文纪律**：不写认错，只摆数据。能算的算死，算不了的标🟡。

## 一、先把目标函数钉死（这次不再绕）

- **分数 = 2000 + 剩余AV = 4000 − elapsed**。3900 ⟺ **elapsed ≤ 100**；3929 ⟺ elapsed ≤ 71。
- 现在的账：**P1 = 89 + P2 = 78 = elapsed 167 → 3833**。要 3900，得砍掉 **67 AV**。
- 我此前只在 P2 抠「扫除 −46」，**从没质疑 P1 的 89**。大人的质疑成立。

## 二、P1 的 89 到底是不是物理必然？——不是，是写死的常数

**引擎取证**：`CFG.tough.barrierUntil = 88` —— 力场闸门是一个**手填的定时数字**，不是算法算出来的。

**但它对应真机制**：破晓力场靠**欢愉伤计数满 16** 解除（§4.7，官方 toast「欢愉伤害可加速解除」），满 16 → 小怪退散 → 真杀 → 保姆白得强普 → 力场破。

**文档自身矛盾（重大发现）**：
- §4.8 推算计数满 16 在 **AV ~130-150**；
- §12.2 实测帧证说力场 **@86-88 就解了，"比模型预期（计数满16）早一大截"**；
- 引擎取了中间值 88 反填，既没实现计数，也没解释为何早。

## 六、整体回答：100 AV 通关卡在哪

| 段 | 现在 | 可压缩 | 依据 |
|---|---|---|---|
| P1 | 89 | **−7**（闸门 88→81） | 计数手算 + 引擎扫描双证 |
| P2 | 78 | −46（砍扫除）已是理论极限；实测 P2 冻结在 1883 说明还能砍更多敌方回合 | 配额制翻案 |
| 合计 | 167 | −7−46 = **114** | 仍 >100 |

**诚实结论**：把已证实的两个提速点全用上，elapsed 约 **114（分数 3886）**，**到不了 3900 的 100**。要走完剩下 14 AV，只能靠：① P2 多砍一次敌方回合（13 金 3967 局总扣仅 33 = 敌方几乎没出手，是练度碾压路径）；② P1 计数在 81 之前满（需更强的计数产出或更集中的欢愉段，🟡 没有帧证）；③ 减伤窗口重排省下的伤害转化为更早击杀（🟡 未量化）。

**所以对用户"100 行动内"的答复**：以当前 5 金练度 + 已钉死的帧证，**算不出 100 以内的确定解**；能算出的是 114 的可达路径 + 三个待攻的 14 AV 缺口。不臆填 3900。

## 九、去编造落地（2026-11-22 晚，大人「以事实为准，不准编」）

> 对引擎做了一次**只减不增**的事实校准：删掉无实据、且删后核心指标不变的编造项；**所有实测锚一律不动**。回归 step1/2/3/4 全过，P1=88.4、阿哈时刻、政策对比逐项与改前一致。

| 项 | 处理 | 依据（为何是"编"） |
|---|---|---|
| `t=81`「破晓退散」插入 | **删除** | 时点靠 1919 帧反推非实测；真实退散=计数满16，已在 dealJoy/onTurn 按 cnt 实现，无需定时插入 |
| `t=112`「兜底清场」插入 | **删除** | 注释自承认"旧主路径被实测推翻"后留的兜底，靠 `s.charge+=320` 凭空造 4 发强普；实测清场 @88.4~89 由狼两动 3+1（mobHit）真机制完成 |
| `takenMobRetreat` 1.3 → **1.0** | **归零** | 失意受伤提高数值未测，1.3 是拿"1轮死"反解的虚构兜底；实测 P1 灰烬力场期 1 轮强普死已由 `takenMobFF=1.0` 闭合 |
| `barrierUntil=88` 注释 | **改口径**（值不动） | 88 是**实测反填**（力场 @86-88 解除、P1 转阶段锚 @89），不是"算出的物理常数"；计数理论最早 @81 与 89 锚冲突，明确不采用 |
| `langQCost=136` 注释 | **标🟡**（值不动） | 单例反解 300→164，实测 P2 另有 76→56=20，两值冲突规则未定，保留仅作对账锚 |

**关键权衡（不修的一项）**：默认 S4 政策把 28 发强普堆在 88.4 一格、狼Q 一拍连开 5 次。内存实验加 0.6AV 冷却可消除堆格（单格 20→4），**但 P1 击杀从 88.4 退化到 115.6**，与实测锚 89 冲突——实测 Q#1@88.4→Q#2@89 的 0.6 间隔是靠"额外回合不占行动条"实现的，引擎用 insert 时间推进模拟，强制间隔会错误占用行动条。**属架构问题非参数问题，按"实测锚优先"不修**，明确留🟡。

**结论**：此次改动是"去掉假数据"，不是"算出新轴"。100AV 的诚实结论（§六，elapsed≈114）不变，不臆填 3900。
