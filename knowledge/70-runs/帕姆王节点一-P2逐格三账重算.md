# P2 逐格三账重算

## 二、三账口径（先别混）

1. **全队笑点池**：阿哈时刻转好活用；P1 里 10→71 那条。P2 段读数在实测表里未单独给，🟡。
2. **保姆累计笑点（充能）**：阈值 80 → 1 发强普；截图 72、"110笑点"、"379笑点"应属这条，但"110/379"是否累计池口径🟡。每发强普 −80（V3.1 §8 账）。
3. **狼隐藏分**：阈值 120 → 额外回合；实测 76(@121)→56(开大)→64→117→120(@166) ✅。这是 P2 唯一逐格能对上的账。

## 三、结论：引擎 P2 三账不能直接用

- **错序**：阿哈#3（P1 遗留）被放 @88.4，实测在 @127；38 AV 错位 → 笑点/隐藏分到账时点全错。
- **堆格**：引擎把狼Q#1强普链全部笑点塞进 @88.4，导致（a）@111 池 84 vs 实测 72（差12）；（b）小怪 @88.4 全清 vs 实测 @166 才清完。
- **后果**：引擎 P2 理论击杀"未"、bossHP 余 316万，而实测 3833 击杀——**引擎的 P2 输出/时点整体失真**，拿它排 3929 收尾轴的前提不成立。

## 四、待核（🟡，打一局收一个）

- 保姆"110/379笑点"到底是累计池还是当前充能 → 下局盯强普前后读数跳变。
- 引擎 @111 池 84 vs 实测 72 的 12 点差：是否专武+20 被重复计 → 修引擎前先确认专武触发次数（"对自身放终结技+20，最多1次，3次普攻后重置"）。
- P1 遗留阿哈时刻（欢愉主+狼欢愉技）推迟到 @127 的机制：是阿哈独立行动条跨阶段保留，还是 P1 结尾未结算完的补算？→ 决定它该记在 P1 还是 P2 账。
