# 07 · 数据源清单与合规边界

> 可信度：✅ 已逐一勘查（2026-11-21）

## 1. 合规边界（先说清楚）

| 行为 | 风险判定 |
|---|---|
| 解本地正式版包、只提数值、纯个人研究 | 违反用户协议第 9 条（禁止反向工程/反编译，营利非营利皆然），但通常不被追究，灰色地带 |
| 把解包文件上传 GitHub / 分发 | 高风险，直接踩协议 |
| 碰测试版 / 未公开内容 | 红线。2026-10 有判例：不正当获取测试包+解包+传播，认定侵害商业秘密，判赔 100 万 |
| 美术/音频/剧情文本 | 版权敏感，不碰 |
| **消费社区已整理的结构化数据** | ✅ 本项目采用路线 |

**关键事实**：`Dimbreath/StarRailData`（解包源头）已于 **2024-10-10 被 Hoyoverse DMCA 下架**（见 https://github.com/github/dmca/blob/master/2024/10/2024-10-10-hoyoverse.md ）。StarRailRes 是其被下架前整理出的成品快照。

> 结论：本项目**不自己解包**，只用现成结构化数据源 + 官方 Wiki。

## 2. 数据源分层

### 第一层：数值底座 —— StarRailRes
- 地址：https://github.com/Mar-7th/StarRailRes
- 许可证：AGPL-3.0
- 结构：`index_new/[language]/` 下 17 个 JSON
  - `characters.json` / `character_ranks.json`（星魂）/ `character_skills.json` / `character_skill_trees.json`（行迹）/ `character_promotions.json`（晋阶与等级）
  - `light_cones.json` / `light_cone_ranks.json` / `light_cone_promotions.json`
  - `relics.json` / `relic_sets.json` / `relic_main_affixs.json` / `relic_sub_affixs.json`
  - `paths.json` / `elements.json` / `properties.json` / `items.json`
- 覆盖：角色/光锥/遗器/技能/行迹/晋阶
- **缺口：无敌方数据**（这是要靠崩铁助手补的部分）
- 用途：练度 → 面板推导层的数值底座

### 第二层：敌方数据 —— 崩铁助手（sr.appfeng.com）
- 地址：https://sr.appfeng.com
- 覆盖：敌方图鉴（属性/抗性/负面抵抗/技能表/形态变体/难度组）、四大深渊模式当期数据（含逐波次精确血量）
- 本期数据截至 2026-11-11，明确标注"取自官方 data-mine，非估算"
- 用途：敌方参数表 + 本期关卡模板
- 状态：✅ 已验证可访问，数据精度满足建模

### 第三层：交叉验证 —— 官方 + 社区 Wiki
| 源 | 用途 |
|---|---|
| HoYoWiki（wiki.hoyolab.com） | 官方机制词条（弱点击破公式、伤害公式基准） |
| 星穹铁道 Wiki / 列车智库（starrail.huijiwiki.com / wiki.biligame.com） | 机制详解、公式交叉验证 |
| GameVika（gamevika.com） | 伤害计算器（公开公式）、bestiary、UID 查询；多语言、更新及时 |
| 米游社 / TapTap / NGA 搬运 | 深度机制帖（回能、嘲讽、buff 结算） |
| Fandom Wiki（honkai-star-rail.fandom.com） | 英文机制词条（Cycle、敌方规则） |

用途：公式与机制的多源比对，防止单一源误导。

### 第四层：面板输入 —— 手动为主，导入为辅
- **初版：手动录入**（用户已确认）
- 后期可选：
  - Enka.network API（按 UID 查玩家面板）
  - GameVika UID 查询（https://gamevika.com/zh-tw/hsr/uid）
  - nanoka（hsr.nanoka.cc，浏览器本地算的练度评估工具）/ HSR-Scanner（官方日志本地解析）
- 用途：把真实练度面板喂给引擎

## 3. 数据源选择决策

| 需求 | 选定源 |
|---|---|
| 角色基础属性/技能倍率/光锥/遗器 | StarRailRes（AGPL，成品快照） |
| 敌方 HP/DEF/SPD/韧性/抗性/技能 | 崩铁助手 sr.appfeng.com |
| 本期深渊关卡配置 | 崩铁助手 challenge 页 |
| 公式与机制校验 | HoYoWiki + 灰机Wiki + GameVika 交叉 |
| 伤害/配装参考实现 | SRCalc（AGPL，只借鉴不复制） |
| 面板导入（后期） | Enka / GameVika UID / nanoka |

## 4. 数据维护风险

- 游戏版本更新（当前 4.7）会导致：新角色、新遗器、敌方数值调整、深渊每期刷新
- 崩铁助手每期深渊数据是**有时效的**，需要定期重新抓取
- 击破公式已定论为单套（3767 基数；942 = 3767÷4、376.75 = 3767÷10 是同式不同单位记法，非"两套体系"），见 04 / 09 修正4；数据源更新时核对基数即可
- 建议：数据落地为本地 JSON 快照 + 记录抓取日期，版本更新时 diff 检查
