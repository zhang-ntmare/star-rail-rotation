## 2. 权威血量（重大纠错）

### 2.1 计算公式（hsr-trend 官方口径）

hsr-trend 说明页原文：

> 单体生命值基于官方底层 `monstervalue.json` 基础值，乘算 `HardLevelGroup` 关卡等级倍率与 `EliteGroup` 精英倍率，并累计同波次怪物数量。若首领具备多阶段（PhaseList），则严格乘算**所有阶段生命值倍率之和**。
> 多阶段 Boss 具有多个战斗阶段，底层数据中 PhaseList 明确记录了各阶段倍率（例如 1.0 + 1.0 = 2.0 倍）。若只计算单段 HPBase 会严重低估 Boss 实际血量。

公式：

```
单管血 = HPBase × HardLevelGroup(Level) × EliteGroup.HPRatio × child.HPModifyRatio
真实总血 = 单管血 × Σ(phase_list[].phase_max_hp_ratio)
```

### 2.3 崩铁助手为什么错（重要教训）

| boss | 崩铁助手值 | 我的算法 | 漏了什么 |
|---|---|---|---|
| 帕姆王 | 8,799,090 | 32550 × 236.534716 × **1.142857** | EliteGroup **2.2**、PhaseList **2.2** |
| 死龙 | 10,998,864 | 46500 × 236.534716 | EliteGroup **2.7**、PhaseList **2.0** |
| 银枝 | 1,374,858 | 5812.5 × 236.534716 | EliteGroup **9.6**、PhaseList **2.0** |

崩铁助手的 "血" 实际是 `HPBase × 等级乘区 × HPModifyRatio` 的**单段图鉴值**，**既没乘精英倍率也没乘阶段倍率**。此前我据此得出"银枝 137 万可信""双源一致"全是错的——所谓"双源"其实是同一套漏乘算法。

**实测印证**：大人直觉"现在版本随便打一下都 100 万"——真实单管 1319 万、总血 2640 万，量级吻合；137 万才是不合常理的那个。

### 2.4 排轴用血量口径

- **斩杀线 / 0T 判定**：用**真实总血**（节点一帕姆王 **42,587,598**）。
- **分阶段模拟**：引擎需按 PhaseList 分两段建模——帕姆王 phase1 倍率 1.0、phase2 **1.2**（即第二段血更多）；死龙与银枝各 1.0。
- **单段伤害占比**：用单管血（帕姆王 19,357,999）。
- 三种说法不可混用；文档与 JSON 统一采用"真实总血"为主值。

### 3.5 机制要点（测试引擎必须表达的状态）

1. **合金保姆充能**：我方笑点 → 保姆充能（1:1）→ 80 触发强化普攻（移除 1 层长效抗菌 + 无视弱点无效强制削韧）。这是**由我方资源事件驱动的第三方单位行动**，引擎需建模。
2. **破晓战队 / 破晓力场**：小怪带 16 层次数盾（攻略数据）；破晓力场存续期间 boss 获得对应属性【伤害免疫】+【弱点无效】。击杀小怪 → 保姆额外回合 + 削 boss 韧性 + 降减伤。
3. **长效抗菌**：减伤层，需靠保姆强化普攻逐层移除；全移除时 boss 受大量伤害（破防窗口）。
4. **蓄力技能**：值日准备中… → 下次行动饱和式大扫除，引擎要能表达"蓄力→延迟释放"。
5. **受击回能**：多个技能"使我方获得笑点"——这是**敌方技能给我方加资源**的反向事件，欢愉队测试会用到。
6. **双阶段血量**：phase1 = 单管 19,357,999，phase2 = 1.2× 单管 = 23,229,599；总血 42,587,598。引擎切阶段时不能重置伤害累计。

## 4. 对欢愉队的天然契合（为什么适合做测试）
