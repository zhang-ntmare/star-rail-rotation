# starRailRotation · 项目记忆

## 项目定位

- 本项目是一个**《崩坏：星穹铁道》（Honkai: Star Rail）的排轴器**，故名 starRailRotation。
- 「排轴」= 规划战斗中队伍的行动顺序 / 输出循环（action order / rotation planning）。
- **输入核心 = 角色练度**（2026-11-21 大人明确）：等级、遗器、光锥、命座、行迹等，或直接给数据面板；由练度推导出面板属性，再进行配轴。
- 链路：练度输入 → 推导面板属性（SPD/双暴/击破等）→ 结合行动条/SP/能量/增益 → 输出行动顺序与技能循环。
- 核心能力：根据角色速度（SPD）、行动条进度、战技点（SP）、终结技能量与增益持续时间等，推演行动序列，辅助配速（speed tuning）与输出循环优化。

## 排轴方法论与知识库（2026-11-22 立）

- **四层递进排轴法（大人定，全项目通用骨架）**：①定目标函数（模式/轮次 or 计分）→②定骨架（双方 SPD+进场条，产出 **baseline = 零拉条唯一解**）→③加拉条（每个算子写"被谁提前几 AV"）→④加机制（场地/boss 技能序列/韧性/力场，**这一层会返工，正常**）→⑤对比优化（期望 vs 实际，凹点 ≤1）。
- 三条补丁：**baseline 必须保留**（量化拉条收益的唯一参照）／**资源台账横穿四层**（SP/能量/笑点/隐藏分，不是第四层才优化）／**机制层是重解约束不是叠加 buff**（会把上一层的"最优"判非法）。
- 三条不确定性分账：①算得出的（必须钉死）②没测的（🟡 + 判别式，打一局收一个）③真 RNG（受击/暴击，唯一计入凹点的）。**凹点能压到 0-1，是因为②被钉死了，不是运气好。**
- **知识库 `knowledge/` 九区**：00-rules（L0 红线/L1 清单/L2 待钉总账）、10-basics、20-action、30-units、40-enemies、50-stage、60-teams、70-runs（产物层）、80-tools。
- **唯一权威原则**：知识库只做索引，正文留在 `docs/`（节点 `source:` 指过去），零复制零漂移。改结论改 docs，节点只更新 updated。
- **召回机制 `tools/kb/kb.py`**（借 ayaka-work 五层模型 + recall 思路，纯标准库）：`build / ls / show / recall / stats`。开工前必做 `recall 角色/怪 机制词`，治"文档里写了但没用上"（爻光普攻回能=战技档就是这么漏的）。
